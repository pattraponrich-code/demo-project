หน้าที่ของ skill นี้คือรับ requirement ดิบจากผู้ใช้ ไล่เรียงความชัดเจนให้ครบก่อนลงมือเขียนเอกสารจริง แล้วมอบหมายงานเขียนไฟล์ให้ subagent `requirement-writer` เป็นคนจัดการ คุณ (main loop) เป็นคนคุยกับผู้ใช้ ไม่ใช่ subagent

## ขั้นตอน

### 1. รับ requirement ดิบ

ถ้าผู้ใช้ยังไม่ได้แนบเนื้อหา requirement มากับคำสั่ง `/new-requirement` ให้ถามผู้ใช้ก่อนว่าต้องการสร้าง requirement เรื่องอะไร

### 2. สำรวจเอกสารเดิมคร่าวๆ

ใช้ `Glob` ดูรายชื่อไฟล์ใน `docs/01-requirements/01-spec/*.md` และ `Grep` ตรวจดูคีย์เวิร์ดหลักของ requirement ใหม่ เพื่อประเมินเบื้องต้นว่ามีเอกสารเดิมที่อาจเกี่ยวข้อง/ทับซ้อนหรือไม่ (ไม่ต้องละเอียดมาก แค่พอประเมินได้ว่าควรถามผู้ใช้เรื่องนี้หรือไม่ในข้อ 4)

### 3. ตรวจสอบความชัดเจนของ requirement

พิจารณาว่า requirement ที่ได้มามีข้อมูลพอสำหรับเขียนเอกสารหรือไม่ เช่น scope (สิ่งที่ทำ/ไม่ทำ), business rule, กลุ่มผู้ใช้เป้าหมาย, เงื่อนไขสำคัญ

**ถ้ามีส่วนใดไม่ชัดเจน** ให้ใช้ `AskUserQuestion` ถามผู้ใช้ทีละประเด็น โดย**ทุกคำถามต้องมีตัวเลือกแนวทางให้เลือกอย่างน้อย 3 ข้อเสมอ** (ห้ามถามคำถามปลายเปิดเฉยๆ โดยไม่มีตัวเลือกแนะนำ) เช่น ถ้าไม่รู้ scope ให้เสนอขอบเขตที่เป็นไปได้ 3 แบบให้เลือก/ปรับ

ทำซ้ำจนกว่าจะมีข้อมูลครบพอที่จะเขียนเอกสารได้

### 4. ประเมินเรื่องเอกสารใหม่ vs เอกสารเดิม

ถ้าจากข้อ 2 พบว่ามีเอกสารเดิมที่ดูเกี่ยวข้อง/ทับซ้อนกับ requirement ใหม่ และยังไม่ชัดเจนว่าควรทำแบบไหน ให้ใช้ `AskUserQuestion` ถามผู้ใช้ โดยเสนอทางเลือกอย่างน้อย 3 แนวทาง เช่น:

1. สร้างเอกสารใหม่แยกต่างหาก (แค่อ้างอิงเอกสารเดิมไว้)
2. อัปเดต/ขยายเอกสารเดิมฉบับที่เกี่ยวข้อง
3. สร้างเอกสารใหม่และทำเครื่องหมายว่า supersede เอกสารเดิมฉบับนั้น

ถ้าจากข้อ 2 ชัดเจนอยู่แล้วว่าเป็นหัวข้อใหม่ล้วนๆ ไม่ต้องถาม ข้ามไปข้อ 5 ได้เลย

### 5. มอบหมายงานให้ subagent เขียนเอกสาร

เมื่อข้อมูลครบและตัดสินใจได้แล้ว (ไม่มีคำถามค้างคาใจอีก) ให้เรียก **Agent tool** โดยระบุ `subagent_type: "requirement-writer"` และส่งข้อมูลต่อไปนี้ให้ครบในพรอมต์:

- หัวข้อ requirement (ภาษาไทย)
- เนื้อหา requirement ที่สรุป/ชี้แจงชัดเจนแล้วทั้งหมด (รวมคำตอบจากคำถามในข้อ 3-4)
- วันที่ปัจจุบัน (YYYYMMDD และ YYYY-MM-DD)
- ผลการประเมินจากข้อ 4: ควรสร้างใหม่ หรืออัปเดตเอกสารเดิมฉบับไหน (ถ้ามี)

ให้ subagent เป็นผู้จัดการสร้าง/แก้ไขเอกสารเอง, อัปเดต `docs/01-requirements/backlog.md`, และเขียน log ที่ `docs/05-log/{YYYYMMDD}-log.md`

### 6. ถ้า subagent รายงานว่าไม่มั่นใจ

ถ้า subagent หยุดทำงานและรายงานกลับมาว่าไม่มั่นใจ (พร้อมตัวเลือกที่เสนอมา) ให้นำตัวเลือกเหล่านั้นไปถามผู้ใช้ต่อผ่าน `AskUserQuestion` แล้วเรียก Agent tool ไปหา subagent `requirement-writer` อีกครั้งพร้อมคำตอบที่ได้ เพื่อให้ทำงานต่อจนเสร็จ

### 7. สรุปผลให้ผู้ใช้ทราบ

หลัง subagent ทำงานเสร็จ ให้สรุปสั้นๆ ให้ผู้ใช้ทราบ:
- ไฟล์ requirement spec ที่สร้าง/แก้ไข (พร้อม path)
- มีการอัปเดต `backlog.md` และ log ของวันนั้นแล้ว
- decision ที่ทำ (สร้างใหม่/อัปเดตเอกสารเดิม) พร้อมเหตุผลโดยย่อ
